# FEC/interleaver identification: literature, implementation and evidence

Reviewed 2026-10-05. This is identification research, **not encryption detection or decryption**. Candidate recognition, exact parameter reconstruction, deinterleaving, error correction, framing and authenticated payload recovery are different acceptance stages.

## Conventional analyst process

1. Preserve original capture and receiver settings. Stabilize carrier/timing and resolve symbol-to-bit mapping or explicitly test alternatives. Record that remaining phase ambiguity, slips and errors affect every later decision. Prefer calibrated LLRs to hard bits when available.
2. Inspect sync markers, length periodicity, repeated frames and protocol headers. A burst boundary is not necessarily a FEC codeword/interleaver boundary. Determine whether whitening/scrambling, differential mapping or puncturing must be reversed first, using a known protocol or separate hypotheses.
3. For linear block-code hypotheses, reshape repeated candidate lengths/offsets into matrices over GF(2), examine rank/null-space/parity-check relations and test syndromes on held-out frames. For RS work, test symbol widths and finite-field conventions over GF(2^m), not ordinary binary rank alone. For BCH, use cyclic/polynomial algebra once family conventions are established.
4. For convolutional codes, test generator polynomials, rate, constraint length, puncturing and output order using parity/syndrome formers and decoder likelihood/path metrics. Turbo/LDPC/Polar require suitable constituent-code/parity/frozen-bit candidate definitions; family classification alone does not specify a decoder.
5. For interleaving, test candidate periods, matrix dimensions, delays and start positions; invert each candidate on a separate branch and check whether redundancy returns. Unknown permutations require reconstruction algorithms and multiple observations. There is no generic entropy test that identifies a permutation of iid uncoded bits.
6. Decode only supported, validated candidates. Evaluate re-encoding residuals, decoder failure indicators and independent CRC/frame checks. Do not use readability as the primary acceptance test: telemetry, compressed voice and ciphertext need not resemble text. Report ambiguity rather than silently picking a winner.
7. If the recovered protocol payload is encrypted, authorized decryption needs its algorithm, key, nonce/IV and relevant framing/authentication data. FEC repairs transmission errors; an interleaver reorders bits; a descrambler reverses a specified whitening transform. None generally recovers an encryption key. Encryption *before* FEC can leave the outer parity structure intact, whereas post-code whitening can conceal it until undone.

Steps 1–7 are the receiver workflow synthesis, not a claim that every paper implements each step. In particular, the current product still lacks full framing, calibrated LLRs and validated payload decoding.

## Shipped experimental contract

`src/fec_identification.py` searches 16 joint candidates plus an unknown class:

- repetition (3,1), Hamming (7,4), Hamming (15,11), convolutional rate 1/2 K=3 generators (7,5 octal), in exactly the documented encoder/bit order;
- no permutation, or **420-bit** row-written/column-read matrix interleavers with 4, 10 or 20 rows (105, 42 or 21 columns);
- matrix block start is supplied by the analyst, default zero, **not automatically verified**. Codeword phase is searched after each inverse-permutation hypothesis. Dimensions outside this list, convolutional/helical/random interleavers, arbitrary code matrices, higher convolutional constraint lengths, puncturing and concatenated codes are unsupported.

The code uses mean syndrome violations, both half-region rates and zero-syndrome word fraction per candidate, plus bit balance, transition rate and autocorrelation at six lags. A standardized 72-feature -> 64-ReLU -> 17-class MLP is trained with Adam. Classical parity evidence is available independently; learned disagreement, weak parity, an ambiguous score gap, degenerate/short input or an unknown class causes abstention. Temperature and acceptance threshold use validation only. Additional parity gates are documented heuristics, not formal likelihood or open-set guarantees.

At least 1680 bits are needed; at most the first 8400 bits after the declared offset are used, rounded down to complete 420-bit blocks. The report gives counts, byte-per-bit SHA-256, model SHA-256, candidate ranking, probability, baseline leader, frame hypothesis and limitations. **A confident class match does not establish the true frame boundary or transmitted permutation.** Shifted streams can retain equivalent parity relations. No candidate is automatically decoded or described as recovered plaintext.

`POST /demodulate` now runs this stage on the full hard-bit region **before** presentation truncates it to 512 bits. `X-DEmod-FEC-Frame-Offset` supplies a bit offset relative to that receiver region. The receiver GUI shows baseline versus model evidence and lets the analyst change the offset. JSON export includes the result. The optional `POST /fec` endpoint accepts `{"bits":"0101...","frame_offset_bits":0}` for independent binary-stream checks; captures/bits are not persisted by the service.

## Training, evaluation and benchmark scope

Run `python research/train_fec_identifier.py` with NumPy. Data is generated in memory per instance; persist only `data/recipes/fec-recipes.json`, weights, checksums and aggregate `research/results/fec_results.json`. Generated feature arrays are ephemeral. Training: 1700 captures; validation: 510. Independent seeds, shared encoder generator and aligned frames. Training lengths 1680/3360/5040 bits; iid bit-flip probabilities 0/.005/.01/.03/.05/.08. Evaluation: 1700 new 3360-bit captures at BER 0/.01/.03/.05/.08. Each class is equally represented, including iid unknown/uncoded bits. Ground truth never enters feature extraction or the inference API.

Compare the hybrid against the minimum hard-syndrome baseline and a separately trained sequence-statistics-only MLP on **the same** 1700 examples. An expensive GF(2) rank baseline is additionally compared on a predeclared one-per-class/BER subset, 85 examples; all four methods are scored on that identical subset. Report full confusion matrices, macro F1, BER strata, acceptance coverage, unknown false acceptance and Wilson 95% intervals. Intervals describe this generator/protocol only and assume independent test examples.

Stress sets use burst errors, shifted frame starts, arbitrary permutations, biased uncoded bits, unsupported Hamming(31,26), whitening and bit insertions/deletions. Acceptance on unsupported/shifted input is **not** correct frame/permutation recovery. In particular, report shifted-frame acceptance rather than claiming robust synchronization.

Published seven-family CNN/DBFCNN accuracies are **not comparable** to our small candidate-set numbers. The DBFCNN dataset is on-request; we have not acquired it, reproduced its network, or run held-out real coded intercepts. Exact current-paper benchmark reproduction, calibrated soft SPP, broader standard code families, arbitrary parameter recovery and downstream BER/CRC acceptance remain future gates. A high synthetic result does not close those gaps.
